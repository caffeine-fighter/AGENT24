# NIGHTMARE LAB 한국어 UX 문구 기준

NIGHTMARE LAB의 일반 사용자 화면은 짧고 자연스러운 해요체를 사용한다. 개발자용 원본 실행 기록을 제외하면 내부 상태 이름과 영문 식별자를 그대로 노출하지 않는다.

## 참고한 국내 서비스 기준

- [토스의 8가지 라이팅 원칙](https://toss.tech/article/8-writing-principles-of-toss): 다음 화면을 예상할 수 있게 쓰고, 의미 없는 단어와 반복을 덜어내며, 소리 내어 말해도 자연스러운 문장을 쓴다.
- [좋은 에러 메시지를 만드는 6가지 원칙](https://toss.tech/article/how-to-write-error-message): 현재 상황, 발생 이유, 사용자가 할 수 있는 다음 행동을 함께 알려준다.
- [GitHub 한국어 문서](https://docs.github.com/ko/repositories/creating-and-managing-repositories/about-repositories): 브랜치, 커밋처럼 국내 개발자가 이미 익숙한 제품 용어는 억지로 번역하지 않는다.

## 제품 문구 원칙

1. 한 문장에는 한 가지 정보만 담는다.
2. 버튼에는 누른 직후 일어나는 일을 쓴다.
3. 빈 상태는 명사형 상태 코드보다 `실험 전`, `확인 전`처럼 짧게 쓴다.
4. 오류는 사용자의 잘못처럼 말하지 않고, 해결 방법을 바로 붙인다.
5. `호환성`, `합성`, `레지스트리`, `PACK` 같은 내부 용어는 쉬운 말로 바꾼다.
6. 위험을 과장하지 않는다. 실험 범위와 확인하지 못한 위험을 함께 밝힌다.
7. 이벤트 이름, 도구 이름, 실행 ID 같은 원본 정보는 개발자용 실행 기록에만 그대로 둔다.

## 대표 교정 예시

| 교정 전 | 교정 후 |
| --- | --- |
| 실행 대기 | 실험 전 |
| 호환 후보 | 지원 가능성 있음 |
| PACK SELECTION AMBIGUOUS | 실험을 하나로 고르지 못했어요 |
| 1 file(s) · 1330 bytes | 파일 1개 · 1.3KB |
| 에이전트에게 시킬 일 | 에이전트에게 맡길 일 |
| 브랜치 또는 커밋 | 확인할 버전 |
| 같은 조건으로 다시 실험 | 같은 내용으로 다시 실행 |
| 진행하지 못함 | 실험 중단 |
| 입력하지 않은 항목이 있어요 | 빈칸을 모두 채워 주세요 |

## 허용하는 기술 용어

`GitHub`, `브랜치`, `커밋 SHA`, `API`, 도구 이름, 이벤트 이름은 정확한 입력과 디버깅에 필요하므로 유지한다. 다만 일반 사용자 영역에서는 용도를 먼저 설명하고, 원본 값은 보조 정보로 보여준다.
